# Next-cycle support portfolio: review guide

Use for broad annual government/local-support strategies, especially when
several researchers return overlapping program catalogs. This is a review
method, not a current eligibility ruling.

## 1. Normalize the evidence before prioritizing

Maintain program identity, jurisdiction, year, notice ID, round, amendment date,
applicant role, original URL, attachment, and checked date. Separate operator,
supplier, beneficiary, and individual expert eligibility. Search amendments and
additional rounds; prefer the exact attachment over a general program page.

An operator recruitment published in September can reveal next-year plans
without opening applications to ordinary companies. Report this as a planning
signal, not either 'nothing announced' or 'apply now'.

## 2. Compare burdens using their real bases

For each percentage record numerator, denominator, cash/in-kind treatment,
rounding, VAT, advance spending, reimbursement timing, guarantees, royalties,
and post-project duties. Use tools for calculations; retain official examples.

Dated examples verified in the 2026 research (recheck for every new call):

- Initial Startup Package general track: ordinary non-capital-region matching
  is expressed against total project cost; cash minimum is also against total.
  Do not interpret it as the same percentage of the grant.
  https://www.bizinfo.go.kr/sii/siia/selectSIIA200Detail.do?pblancId=PBLN_000000000117819
- Didimdol first call: cash minimum is a share of the applicant contribution,
  not the whole project. Later rounds/tracks must be evaluated independently.
  https://www.bizinfo.go.kr/sii/siia/selectSIIA200Detail.do?pblancId=PBLN_000000000116971
- Ulsan AI development notice: matching wording and its numerical example
  require careful comparison with the cited R&D rules. Preserve ambiguity
  rather than silently imposing another program's formula. Hiring, IP,
  software registration, certification and multi-year monitoring can dominate
  the practical burden for a solo firm.
  https://uipa.or.kr/webuser/business/view.html?bd_id=23510&page=

Do not turn support into profit or a consortium ceiling into supplier revenue.
Do not recommend corporate conversion or hiring solely to clear a grant gate.

## 3. Provider and workforce traps

- Permission for uncertified training providers does not expressly establish
  that every one-person sole proprietor qualifies. Course approval, premises,
  instructors, attendance, completion and reimbursement administration remain
  separate checks.
- Annual training operation is not continuous provider recruitment. Distinguish
  original planned dates from actual second/third-round dates.
- Training tables can carry geographic reimbursement rates and practical-hour
  thresholds missing from extracted prose. A minimum for AI classification is
  not necessarily the minimum duration of every course. Inspect omitted tables.
- A research-department rule permitting one researcher or a founder exception
  may coexist with a requirement for another permanent worker doing sales or
  other nonresearch business. Read both before recommending a solo structure;
  do not assume 'representative director' explicitly includes every sole owner.
- If procurement documents simultaneously prohibit joint contracting and give
  joint-bid conditions, retain both clauses and require an amendment or written
  answer before choosing the contract structure.

## 4. Close the parallel-review loop on actual files

1. Read each research report and structured catalog, not only completion logs.
2. Send bounded correction requests for decision-changing gaps. When one worker
   has stronger evidence, pass its exact file/URL to the other rather than
   duplicating broad searches.
3. Compare revised prose and JSON. A worker can correct prose while a JSON patch
   fails; a successful process exit is not evidence that all artifacts changed.
4. Reconcile corrections into the manager-owned catalog with provenance. Do not
   edit another worker's files merely to make its self-report appear correct.
5. Freeze the report's reviewed inputs. Mark pending specialist replies and any
   manager-direct corrections honestly; never claim the full review loop closed
   while one correction response is still outstanding.
6. If a later reply changes the approved message or attachment, obtain renewed
   sending approval rather than silently replacing the deliverable.

## 5. Citation and catalog QA

Merge URLs into a parent-owned ledger; never concatenate child citation IDs.
Keep stable IDs while deriving a cited-only view if strict verification requires
it. Preserve quotes/provenance in that view. Render source lists mechanically.

Strict citation success checks references and mapping, not semantic coverage.
A long catalog citing sources only in each heading can pass a mapping check
while many individual claims remain ungrounded. Review eligibility, amounts,
deadlines and exclusions against the attached evidence; keep evidence grades
and unresolved conditions visible. A quoted fragment proving a title alone is
not proof of every rule attributed to that source.

Count catalogs programmatically. Label round/role records as review records,
not distinct opportunities or eligible applications. Deduplicate the same round
using the stronger evidence while preserving genuinely different roles.

Keep HTML structural checks, static design checks, actual screen/print review,
and authorized delivery as separate verification states. Never substitute one
for another.
