# bitlabs 정부지원사업 모니터

한국 정부·공공기관의 신규 지원사업을 매일 증분 조사한다. 목록과 HTML 본문으로 먼저 적합성을 판정하고, bitlabs와 관련된 공고에 한해서만 PDF/HWP 첨부파일을 읽는다.

## When to Use

- bitlabs에 맞는 신규 정부지원사업을 정기적으로 조사할 때
- 마지막 성공 점검 이후 새로 게시되거나 수정된 공고만 확인할 때
- 신규 공고의 지원자격·기간·금액·컨소시엄 조건을 검증할 때

일회성 전체 공고 재조사나 이미 마감된 사업의 일반 정보 수집에는 사용하지 않는다.

## Prerequisites

- 기준 시간대: `Asia/Seoul`
- 상태 파일: `$HERMES_HOME/state/bitlabs-government-support-monitor.json`
- 보고서 위치: `$HERMES_HOME/reports/government-support/YYYY-MM-DD.md`
- 공식 출처: 기업마당, K-Startup, IRIS, NIPA, KIAT, KHIDI, 울산광역시, 울산테크노파크, 울산정보산업진흥원, 울산경제일자리진흥원, 스마트공장 사업관리시스템
- 인용은 `grounded-citations` 스킬을 적용한다.

## Relevance Contract

다음 조건을 모두 충족해야 관련 공고로 판정한다.

1. **신청 주체 적합:** 전국 기업 또는 울산 소재 기업이 신청할 수 있고, bitlabs와 같은 중소기업·소상공인·창업기업·IT/SW 공급기업이 배제되지 않는다.
2. **사업 분야 적합:** AI, ICT/SW, SaaS, 제조데이터, MES, 스마트공장, 자동차 공정, 비전·열화상 검사, 산업 AI, 의료AI·디지털헬스, AI 교육·컨설팅, 창업 사업화, 기술개발 R&D 중 하나 이상과 직접 관련된다.
3. **실행 가능:** 접수 중이거나 접수 예정이며, 지역·업력·업종·인력·매출·선행과제·투자·인허가·컨소시엄 조건상 신청 가능성이 있다.

타 지역 한정, 이미 마감, 포상만 제공, 입찰·용역 발주, 신청 주체가 지자체·대학·병원으로 제한된 공고는 제외한다. 다만 bitlabs가 공식 공급기업·공동연구기관으로 참여할 수 있다고 본문에 명시된 경우는 조건부 후보로 남긴다.

## Procedure

### 1. 상태 불러오기

`read_file`로 상태 파일의 `last_successful_cutoff`, `seen_ids`, `seen_updates`, `source_status`를 읽는다. 파일이 없으면 현재 시각을 기준선으로 생성하고 과거 공고를 소급 보고하지 않는다. 완료 기준은 이번 점검의 기준선이 하나로 확정된 상태다.

### 2. 목록 텍스트만 증분 수집

각 공식 출처의 공고 목록을 텍스트로 확인한다. 마지막 성공 기준선 이후 게시·수정된 항목을 수집하되, 지연 등록을 잡기 위해 48시간 겹침 구간을 사용하고 `seen_ids`로 중복 제거한다. 이 단계에서는 PDF/HWP/ZIP을 열거나 다운로드하지 않는다.

공고별로 출처, 공고 ID, 제목, 게시일, 수정일, 접수 시작·종료일, HTML URL을 기록한다. 페이지를 끝까지 넘겨 기준선 이전 항목에 도달했는지 확인한다. 완료 기준은 모든 출처가 성공 또는 실패로 명시된 상태다.

### 3. HTML 본문으로 1차 적합성 판정

신규·수정 공고의 HTML 텍스트에서 사업개요, 신청대상, 지역, 업력, 업종, 지원내용, 신청기간, 컨소시엄 요건을 읽는다. `Relevance Contract`를 통과하지 못한 공고는 제외 사유만 상태에 저장하고 첨부파일을 열지 않는다.

HTML에 핵심 조건이 없으면 관련성이 명백한 제목·요약일 때만 `조건 확인 필요` 후보로 남긴다. 완료 기준은 각 신규 공고가 `관련`, `조건부`, `제외` 중 하나로 분류된 상태다.

### 4. 관련 공고만 첨부파일 검증

`관련` 또는 `조건부` 공고에 한해서만 PDF/HWP를 읽는다. 지원금액, 자부담, 세부 자격, 선행실적, 인력·매출 요건, 컨소시엄 구성, 제출 마감시각, 중복수혜 제한을 확인한다.

첨부파일을 읽은 뒤 자격이 맞지 않으면 제외로 변경하고 이유를 기록한다. 첨부파일이 열리지 않으면 확인되지 않은 내용을 추측하지 말고 `첨부 검증 실패`로 표시한다. 완료 기준은 보고 대상의 핵심 자격과 마감이 공식 원문으로 검증된 상태다.

### 5. 중복과 변경 이력 처리

공고 ID와 정규화 URL을 우선 키로 사용한다. 같은 사업의 재공고·수정공고는 새 항목이 아니라 변경 이벤트로 묶고 달라진 자격·기간·지원내용만 보고한다. 완료 기준은 한 사업이 보고서에 한 번만 나타나는 상태다.

### 6. 보고서 작성

신규 관련 공고가 있으면 다음 순서로 한국어 존댓말 보고서를 작성한다.

1. 결론과 오늘 확인할 행동
2. 신규·수정 공고 표: 사업명, 상태, 마감, 지원내용, 자격, bitlabs 적합 이유, 위험요인
3. 추천 우선순위: 마감 임박도 → 중요도 → 매출 영향
4. 제외한 유사 공고와 제외 이유
5. 출처별 수집 실패와 확인 공백
6. 공식 출처 링크

신규 관련 공고가 없으면 `오늘 새로 확인된 bitlabs 관련 정부지원사업 공고는 없습니다.`와 출처 실패 여부만 보고한다. 기밀정보는 제외하거나 식별 불가능하게 마스킹한다.

### 7. 상태 갱신

모든 출처의 성공·실패를 기록하고, 성공한 출처만 해당 출처의 커서를 전진시킨다. 확인한 모든 공고 ID와 수정시각을 저장한다. 전체 점검의 `last_successful_cutoff`는 핵심 출처가 성공했을 때만 갱신한다. 완료 기준은 다음 실행이 같은 공고를 신규로 재보고하지 않는 상태다.

## Pitfalls

- 목록 단계에서 첨부파일부터 내려받지 않는다.
- 기업마당은 `rows=50` 요청에도 실제 15개 행을 반환할 수 있다. 요청한 페이지 크기를 신뢰하지 말고 실제 공고 행 수·마지막 등록일·다음 페이지 링크로 48시간 겹침구간 끝까지 검증한다.
- 스마트공장 SPA 목록이 비면 공개 JavaScript에서 `/usr/bg/ba/ma/bsnsPbanc/selectBsnsPbancPage.do`와 `/usr/bg/ba/ma/bsnsPbanc/selectBsnsPbancDtlPage.do` 호출 형식을 확인한다. 상세 조회는 `key=info`, `pbancId`, `pbancSn`을 사용하며 반환된 HTML 본문으로 적합성을 먼저 판정한다. 정적 chunk 해시는 변경되므로 하드코딩하지 않는다. 목록의 미래 공고일은 현재 신규로 보고하지 않는다.
- KIAT 공식 목록/상세를 urllib의 JSON·reactDivision 헤더로 요청해 HTTP 500이 나면, 별도 JSON 헤더 없는 `requests.get(url, timeout=60)`으로 재시도한다(2026-09-16 복구 확인). 정상 공고 행/상세 본문을 확인하고 초기 실패와 복구를 함께 남긴다.
- 스마트공장 상세 `atchFileId` 공란→값 변경은 첨부 메타데이터 변경으로 보존하되 HTML·접수기간이 같으면 지원조건 변경으로 단정하지 않는다. 지역 부적합으로 제외된 공고는 이 경우에도 첨부를 열지 않고 내용 미검증을 명시한다.
- KIAT K-PASS가 접수기간만 표시하면 KIAT 공식 홈페이지의 `/front/board/boardContentsListAjax.do?board_id=90&miv_pageNo=1&miv_pageSize=10` 목록을 대안으로 확인한다. 목록 전체 업데이트 시각은 개별 공고 수정일로 사용하지 않는다.
- HTTP 200이나 홈페이지 미리보기만으로 출처 성공을 선언하지 않는다. 울산TP 지원사업 목록이 비어 있으면 페이지의 `/sub02/js/re_ancmt.js`가 가리키는 공식 `/proc/re_ancmt/list.php`를 확인한다. 고정 공고를 일반 최신 공고와 분리해 페이지 경계를 검증한다.
- 울산시 고시공고 `contents.ulsan?mId=001004002000000000`는 `/u/rep/transfer/notice/list.ulsan?mId=001004002000000000`로 리디렉션된다. 페이지 이동은 최종 목록 URL에 `curPage=N`을 붙인다(원 contents URL에서는 curPage가 소실되어 첫 페이지 반복 가능). 상세 URL도 최종 경로 기준으로 해석하고 ID는 숫자와 `gosiGbn`을 함께 쓴다(같은 숫자가 A/N에 중복 존재). 반복 페이지는 행 ID 집합으로 감지한다.
- 울산TP 공식 API가 JSON 객체 대신 `true`만 반환하면 정상 목록으로 간주하지 말고 `www.utp.or.kr` 호스트로 재시도한다. www 호스트도 `true`이면 공식 JS의 `cache:false` 요청과 같이 `&_=<현재 epoch 밀리초>` 캐시버스터를 추가해 재시도한다(2026-09-13 실제 복구 확인). `code=OK`와 `data` 행 배열을 확인해야 성공이다. API의 `is_gonggi=Y` 고정 항목을 모두 지난 다음 `N` 일반 항목의 게시일 경계를 확인한다.
- 2026-09-14 UTP는 www+캐시버스터도 `true`였으나 non-www `https://utp.or.kr/proc/re_ancmt/list.php?task=list&page=N&s_state=&sear=&_=<epoch ms>`로 복구되었다. 양 호스트를 모두 시도하고 `code=OK`·data 배열 검증 후 성공 처리한다. 목록 API의 접수기간·본문을 전일과 비교하여 변경 발견 시 `task=getItem&seq=<ID>&_=<epoch ms>`를 조회한다. 상세에는 `last_modified_dt`가 실제 제공될 수 있으므로 UTP 전체를 수정시각 미노출로 단정하지 않는다. 587은 9/14 수정으로 마감이 10/31에서 9/11로 단축됐으며, 본문 '예산 소진 시까지' 문구가 남아 있어도 목록 종료 상태·상세 신청종료일과의 불일치를 명시한다.
- 울산소식 전일 HTML 비교 시 조회수의 천단위 쉼표까지 제거하고(`조회수\\s*[\\d,]+`), 본문 뒤 공통 `최종수정일`·만족도·관련사이트 영역을 제외한다. 조회수·푸터 링크 변경을 사업 수정으로 오판하지 않는다.
- 울산경제일자리진흥원(UBPI) 상세 HTML 전일 비교 시 `조회\s*[\d,]+`와 첨부 `Down\s*:\s*[\d,]+`는 동적 카운터로 제거한다. 2026-09-15 3541·3540은 이 카운터만 달라졌으므로 모집조건 수정으로 보고하지 않는다. 증거 인용은 정규화하지 않은 원문에서 추출해야 verbatim 검증이 통과한다.
- 스마트공장 목록 중복제거는 `(pbancId, pbancSn)` 복합키로 한다. 같은 pbancId에 다른 pbancSn(추가모집·유형별)이 실제 존재하므로 pbancId만으로 행을 덮어쓰지 않는다. 기존 상태 ID 형식을 바꾸지 않아도 관측 증거에는 두 필드를 모두 보존한다.
- K-Startup 상세를 모두 `bizpbanc-ongoing.do?schM=view&pbancSn=...`로 요청하면 모집마감 항목은 HTTP 200이어도 제목/본문 없이 38자 정도만 반환할 수 있다. 해당 항목은 `bizpbanc-deadline.do`로 재요청하고 `지원분야`·`신청방법 및 대상`·실제 제목으로 상세 유효성을 검증한다(2026-09-17 179264·179239 복구). `.bizpbanc_view`/`#contents` 선택자가 없을 때 전체 페이지 대신 `지원분야`부터 `본 저작물은` 이전까지 본문을 분리해 동적 메뉴·기관정보 팝업을 해시에서 제외한다.
- PDF의 모든 페이지가 비어 있지 않더라도 검증 완료가 아니다. 이미지 포스터는 링크 등 129자만 추출되는 경우가 있다(2026-09-17 K-Startup 179280 ETRI 공모). 페이지당 텍스트가 지나치게 적으면 렌더 이미지까지 직접 확인하고 이미지 판독 증거를 별도로 남긴다.
- K-Startup 목록의 등록일자와 상세 본문 내 원기관 공고일·접수시작일은 다를 수 있다. 포털 신규 등록은 별도 이벤트로 기록하고 과거 원기관 사업이 오늘 처음 생겼다고 표현하지 않는다. 상세 상단 접수마감과 선정절차 내 접수기간이 상충하면 둘 다 인용하고 보수적 마감 및 주관기관 확인 필요를 표시한다.
- UIPA·UBPI 상세 HTML 비교에서는 `이전글`/`다음글` 탐색 영역도 제외한다. 새 게시물이 생기면 기존 상세의 이전글 링크만 바뀔 수 있으므로 카운터 정규화 후에도 이를 실질 수정으로 오판하지 않는다(2026-09-16 UIPA 24980, UBPI 3541 확인).
- 해외 프로그램은 PDF의 마감 시간대를 반드시 확인한다. 2026-09-18 K-Startup 179294 실리콘밸리 GTM은 HTML `10/9 18:00`에 시간대가 없으나 공식 PDF는 `미국 서부 시간 기준`이라고 명시한다. 둘을 같은 한국시간으로 저장하지 말고, 원문 시간대·포털 표시·보수적 제출 권고를 구분한다. 제품·서비스 보유뿐 아니라 한국/미국 매출 필수 요건도 대표 경력과 분리해서 검증한다.
- 게시일·접수기간을 수정시각으로 대신 저장하지 않는다. 수정시각 미노출은 공백으로 명시하고, 기준선 이전 미관측 항목은 신규 발생으로 단정하지 않는다.
